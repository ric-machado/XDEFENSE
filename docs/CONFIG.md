# XDEFENSE — Configuration Reference

All XDEFENSE configuration is done through environment variables in the `.env` file at the repository root. The file is generated automatically by `./scripts/setup.sh` and is **never committed to git**.

---

## The `.env` File

```bash
# Create from template (manual setup only — setup.sh does this automatically)
cp .env.example .env
```

The `.env` file is loaded by Docker Compose at startup. Every `CHANGE_ME_*` placeholder must be replaced with a strong random value before starting the stack.

> **Security rule:** `.env` is in `.gitignore` and must never be committed. It contains all secrets for the platform.

---

## Environment Variables Reference

### PostgreSQL

| Variable | Default (template) | Description |
|---|---|---|
| `POSTGRES_USER` | `postgres` | PostgreSQL superuser name |
| `POSTGRES_PASSWORD` | `CHANGE_ME` | PostgreSQL superuser password (generated by `setup.sh`) |
| `POSTGRES_APP_PASSWORD` | `CHANGE_ME` | Password for the `xdefense_app` application role |
| `POSTGRES_DB` | `xdefense` | Database name (do not change) |

The application role `xdefense_app` has `GRANT USAGE` on all 13 schemas and `GRANT ALL PRIVILEGES` on all tables. The superuser is used only by migrations and admin scripts.

### PgBouncer (Connection Pooler)

| Variable | Default | Description |
|---|---|---|
| `PGBOUNCER_AUTH_USER` | `xdefense_app` | Application user that PgBouncer authenticates |
| `PGBOUNCER_AUTH_PASSWORD` | `CHANGE_ME` | Must match `POSTGRES_APP_PASSWORD` |

PgBouncer listens on port 6432 (internal) and proxies to postgres:5432. The backend always connects through PgBouncer, never directly to PostgreSQL.

### Redis

| Variable | Default | Description |
|---|---|---|
| `REDIS_PASSWORD` | `CHANGE_ME` | Redis authentication password |
| `REDIS_URL` | `redis://:PASSWORD@redis:6379/0` | Full Redis connection URL (constructed from password) |

Redis is used for: session storage (Phase 8), response caching, rate limiting, distributed locks, and pub/sub.

### RabbitMQ

| Variable | Default | Description |
|---|---|---|
| `RABBITMQ_PASSWORD` | `CHANGE_ME` | RabbitMQ password for the `xdefense` vhost user |
| `RABBITMQ_URL` | `amqp://xdefense:PASSWORD@rabbitmq:5672/xdefense` | Full AMQP connection URL |

RabbitMQ management UI is accessible at http://rabbitmq:15672 (internal). Username is `xdefense`, password is `RABBITMQ_PASSWORD`.

### Application (Node.js Backend)

| Variable | Default | Description |
|---|---|---|
| `PORT` | `9292` | Port the Node.js backend listens on (do not change without updating docker-compose.yml) |
| `NODE_ENV` | `production` | Node.js environment (`production` or `development`) |
| `DB_DIR` | `/data` | Path inside the container where SQLite databases are stored |
| `APP_SESSION_SECRET` | `CHANGE_ME` | Express session secret — minimum 64 characters, hex string recommended |
| `XDEFENSE_DB_ENGINE` | `sqlite` | Database engine selector: `sqlite` or `postgres` |
| `XORCISM_ALLOW_REGISTER` | `0` | Set to `1` to allow self-registration; keep `0` for production |
| `XORCISM_BASE_URL` | `https://localhost` | Public base URL used in emails and callbacks |

#### `XDEFENSE_DB_ENGINE`

> **Important:** This variable currently controls only the Python layer (importers, connectors, TAXII). The Node.js backend always uses SQLite regardless of this setting (Stage 2 migration is pending — see [DATABASE_BACKENDS_STAGE2.md](DATABASE_BACKENDS_STAGE2.md)).
>
> Setting `XDEFENSE_DB_ENGINE=postgres` causes Python to write to PostgreSQL while Node reads from SQLite — a real data divergence. Keep `sqlite` for all deployments until Stage 2 is complete.

### Vault (Field Encryption)

| Variable | Default | Description |
|---|---|---|
| `VAULT_KEY` | `CHANGE_ME` | AES-256-GCM encryption key for sensitive fields — minimum 32 bytes, hex string |

The vault key encrypts sensitive fields in the database (API keys, credentials stored for connectors). Losing this key means losing access to encrypted data. Back it up separately from the database.

### TAXII Server

| Variable | Default | Description |
|---|---|---|
| `TAXII_HOST` | `0.0.0.0` | IP the TAXII Flask server binds to (do not change) |
| `TAXII_PORT` | `5000` | Internal port (do not change; Nginx proxies `/taxii2/`) |
| `TAXII_AUTH` | `1` | Set to `0` to disable TAXII authentication (not recommended) |
| `TAXII_PASSWORD` | `CHANGE_ME` | Password for TAXII discovery endpoint authentication |
| `TAXII_BACKEND` | `sqlite` | TAXII storage backend: `sqlite` (current) or `postgres` (future) |
| `TAXII_DB` | `/data/taxii.db` | Path to TAXII SQLite database inside container |

### Grafana

| Variable | Default | Description |
|---|---|---|
| `GRAFANA_PASSWORD` | `CHANGE_ME` | Grafana admin password |

Grafana is accessible at https://localhost/grafana. Username is `admin`.

### Optional External Integrations

| Variable | Default | Description |
|---|---|---|
| `NVD_API_KEY` | _(empty)_ | NVD API key for faster CVE imports (optional; works without key at lower rate) |
| `TAXII_PROXY_URL` | `http://taxii:5000` | Internal URL of the TAXII server |
| `OSV_API_URL` | `https://api.osv.dev` | OSV vulnerability database API |
| `CIRCL_API_URL` | `https://vulnerability.circl.lu` | CIRCL CVE-Search API |

### SMTP (Email Notifications — Optional)

| Variable | Default | Description |
|---|---|---|
| `SMTP_SERVER` | `smtp.example.com` | SMTP server hostname |
| `SMTP_PORT` | `587` | SMTP port (587 = STARTTLS, 465 = SSL, 25 = plain) |
| `SMTP_USERNAME` | _(empty)_ | SMTP authentication username |
| `SMTP_PASSWORD` | _(empty)_ | SMTP authentication password |
| `SMTP_FROM` | `noreply@xdefense.local` | From address for outgoing emails |

Leave SMTP variables empty to disable email notifications.

### AI / Ollama (Optional — `--profile ai`)

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_URL` | `http://ollama:11434` | Ollama API base URL |
| `OLLAMA_MODEL` | `llama3` | Default LLM for inference |
| `OLLAMA_EMBED_MODEL` | `nomic-embed-text` | Embedding model for semantic search |

These variables are only used when the AI profile is active. The platform functions fully without them.

### Logging

| Variable | Default | Description |
|---|---|---|
| `LOG_LEVEL` | `INFO` | Log verbosity: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `PYTHONUNBUFFERED` | `1` | Forces Python stdout/stderr to be unbuffered (keep at 1) |

## Services Configuration

### Resource Limits

Defined in `docker-compose.yml` under `deploy.resources.limits`:

| Service | CPU | Memory |
|---|---|---|
| backend | 2 | 2 GB |
| postgres | 4 | 4 GB |
| redis | 1 | 512 MB |
| rabbitmq | 2 | 1 GB |
| connector-runner | 1 | 1 GB |
| python-worker | 1 | 512 MB |
| scheduler | 1 | 512 MB |
| nginx | 1 | 256 MB |
| taxii | 1 | 512 MB |
| prometheus | 1 | 512 MB |
| grafana | 1 | 512 MB |
| loki | 1 | 256 MB |
| tempo | 1 | 256 MB |

Adjust these in `docker-compose.yml` for your hardware.

### Volumes

| Volume | Used by | Contents |
|---|---|---|
| `xdefense-data` | backend, scheduler | SQLite databases, uploaded files, bootstrap credentials |
| `postgres-data` | postgres | PostgreSQL data directory |
| `redis-data` | redis | Redis persistence (AOF) |
| `rabbitmq-data` | rabbitmq | RabbitMQ messages and definitions |
| `pgbouncer-data` | pgbouncer | PgBouncer config |
| `backup-data` | backup | Daily PostgreSQL dumps |
| `grafana-data` | grafana | Grafana dashboards and settings |
| `prometheus-data` | prometheus | Metrics TSDB |
| `loki-data` | loki | Log storage |
| `tempo-data` | tempo | Trace storage |
| `ollama-data` | ollama | Downloaded LLM model weights |

### Networks

| Network | Connected services |
|---|---|
| `xdefense-frontend` | nginx, backend, taxii |
| `xdefense-backend` | backend, taxii, connector-runner, python-worker, scheduler, postgres, pgbouncer, redis, rabbitmq |

Services on `xdefense-frontend` are reachable from outside via Nginx. Services on `xdefense-backend` are isolated from direct external access.

### Logging

All containers use the `json-file` driver with rotation:

```yaml
logging:
  driver: json-file
  options:
    max-size: "50m"
    max-file: "5"
```

Logs are collected by Loki for search via Grafana.

## Nginx Configuration

The Nginx configuration is at `nginx/nginx.conf`. Key settings:

- HTTP :80 → 301 redirect to HTTPS
- HTTPS :443 with TLS 1.2/1.3
- HTTP/2 enabled
- Brotli and Gzip compression
- Security headers: HSTS, X-Frame-Options, X-Content-Type-Options, CSP
- `client_max_body_size 100m` (for CVE feed uploads)
- Upstream `backend` → `backend:9292`
- Upstream `taxii` → `taxii:5000`, path `/taxii2/`

To apply configuration changes:

```bash
docker compose exec nginx nginx -t          # test config
docker compose exec nginx nginx -s reload   # reload without downtime
```

## PostgreSQL Schemas

The database `xdefense` contains 13 schemas, one per logical domain:

| Schema | Purpose |
|---|---|
| `xorcism` | Core platform: users, RBAC, organizations, API keys |
| `xvulnerability` | CVE, NVD, EPSS, KEV, OVAL data |
| `xattack` | MITRE ATT&CK (tactics, techniques, mitigations) |
| `xmalware` | Malware samples, families, YARA rules |
| `xincident` | Incidents, events, timeline |
| `xthreat` | STIX objects, IoCs, campaigns, actors |
| `xoval` | OVAL definitions and results |
| `xwindows` | Windows security patches |
| `xcompliance` | Frameworks (NIST CSF, ISO 27001, CIS, EBIOS RM) |
| `xticket` | Ticketing and workflow |
| `xid` | Identity: WebAuthn, TOTP, OIDC |
| `xjob` | Job queue and scheduling |
| `xagent` | Endpoint agent enrollment and telemetry |

Initialization scripts are in `postgres/init/`. Flyway migrations are in `flyway/migrations/`.
